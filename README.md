# 终南健身 · OpenChamber 扩展

OpenChamber 2.7.0+ 的人数采集与本地预测扩展，支持 Mac 和 Windows。

在 **设置 → 扩展 → 添加扩展** 中粘贴本仓库地址，允许运行本地服务。侧栏显示当前人数、每天的历史曲线与今日预测。

- 每分钟采集一次，连续相同人数合并记录，内部保留最近 30 天。
- 一个有效训练日后开始预测，逐步学习每周七天及周末差异。
- 本地统计模型，不调用 AI、不消耗模型额度。
- 关闭侧栏仍持续采集；退出 OpenChamber 或休眠时停止。
- 不提供 MCP，不需要 Python 或独立托盘程序。
- 首次运行会导入之前终南健身托盘应用的已有记录。
- Git 地址安装从 v0.1.5 起自动检查并安装本仓库的新版本，启动时及每 30 分钟检查一次。

分享记录：打开侧栏「终南健身」，点击 **导出记录**，文件会保存到下载文件夹，可用 **打开文件夹** 找到后发给对方。对方更新插件后点击 **导入记录**，选择收到的 JSON 文件即可。

导入、导出入口只在扩展面板中显示，工作状态面板不显示。导入仅补充最近 30 天缺少的分钟，同一分钟保留本机已有记录；重复导入不会增加重复数据。导入完成后自动重新计算预测，原有采集继续运行。

旧版本需先在 OpenChamber 中更新到 v0.1.5 一次，之后自动更新会重启扩展服务、刷新面板，历史保存在独立数据目录中。自动更新跟随安装时的 Git 分支；固定到标签、本地有改动、需要新增权限或提高最低宿主版本的更新仍交由 OpenChamber 处理。

开发：`bun install && bun run verify`，开发检查使用 Node 24。已打包的 `panel/` 和 `service/` 随仓库提供，安装时无需 Bun 或系统 Node。

`bun scripts/serve-test.ts` 启动隔离的侧栏验收页，包含日期切换、延迟读取、失败恢复与深浅色切换，用示例数据验证界面，不写入实际记录。GitHub Actions 分别在 Mac 和 Windows 检查源码、存储、模型和打包后的后台。

`bun scripts/serve-transfer-test.ts` 启动导入／导出的隔离验收服务，使用临时数据库和临时下载文件夹，启动输出包含测试文件所在目录。

预测缓存必须比较历史 5 分钟样本的时间与人数，不能只按日期缓存；导入改变历史后要重建模型和回测结果。回归验证要比对预测数值，而不只是训练天数。自动更新仅作用于宿主管理的 Git 安装目录，验证来源、清单和打包文件后执行 fast-forward，扩展权限或宿主要求变化需保留宿主的批准流程。

### v0.1.5

- 修复同一天导入历史后，训练天数更新但曲线仍沿用旧模型的问题；已导入的数据无需重新导入。
- Git 安装自动从 GitHub 更新，更新后自动重启扩展服务、刷新面板。
- 增加曲线数值、实际打包预测线程及浅克隆自动更新的回归检查。

### v0.1.4

- 扩展面板增加历史导入、导出和打开导出文件夹入口。
- 按分钟合并历史，本机记录优先；文件完整校验后一次写入，保留缺采空档和连续同值压缩。
- 支持超过宿主单次传输限制的历史文件，导入后自动重算预测。

### v0.1.3

- 修正扩展身份字段的位置，兼容要求 `contributes.panel.id/name/icon` 的 OpenChamber 构建，解决添加时 `panel.id` 校验失败和 HTTP 400。
- 安装检查增加原始清单校验，不依赖新版 SDK 的字段自动转换。

### v0.1.2

- 实测曲线以 5 分钟均值平滑显示，预测虚线接到最近有效的实测点。
- 鼠标悬浮显示时间、人数和实测／预测类型；真实缺采保留空档。

### v0.1.1

- 预测线程退出或长时间不响应后，下次采集会重建线程；旧的失败预测不会继续显示。
- 初始模型优先借用同类工作日或周末的记录，近期数据权重更高。
- 快速切日期、切主题和跨午夜时，日期与曲线保持一致；读取失败保留已成功加载的记录。
- 服务重启后仍遵守一分钟请求间隔；同一秒的成功和失败按实际先后顺序显示。
- 兼容早期逐分钟历史库，导入时保留插件较新的记录；旧库导入失败不阻断当前采集。
